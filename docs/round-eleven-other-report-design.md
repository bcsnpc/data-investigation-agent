# Two-report comparison design for review

Prepared 2026-10-09. Design only; no two-report procedure has been enabled.
Current `OTHER_REPORT` requests remain a named unimplemented-route refusal.
The Phase A quality gate must pass before estate evidence is gathered.

The contract needs a typed pair of independently validated scopes, with
`PRIMARY` and `COMPARISON` sides. Each side carries the existing target/figure,
report binding, declared-context inventory, precision and provenance contracts.
Clarification addresses a named side; it must not overwrite the other side's
NUMBER confirmation. Two different figures for one cell remain ambiguous.
This requires an explicit consumer contract extension before implementation,
rather than passing a second scope beside the current single-scope contract.

Keep two independently established referents on one persistent ticket. Each side
has its own report/page, visual/cell address, declared context, reported-state
provenance and stated precision. The engine never chooses the other report or
uses an equal numeral to select either visual. Batch unresolved number/report
questions; preserve alternatives until the user answers. Existing single-report
scope validation remains the consumer on both sides.

Reproduce each display under its own complete declaration inventory, with saved
slicer-default qualifications and unknown/conditional forms preserved. Record
served quantities and attestations separately. A match is a reproduction of the
declared scenario, not proof of the user's live bookmark, selection or RLS state.
An unsupported predicate or incomplete inventory stops that side faithfully.

Resolve both declared upstream paths, then locate their first shared asset by
binding identity. Names, equal results and shared containers are insufficient.
Compile equivalent quantities on both branches; measure definition, scope, grain,
join multiplicity and deduplication must be explicit. A shared table does not
make two different measures comparable. Missing faithful quantity translation
ends at a named NOT_COMPARABLE boundary with both partial paths preserved.

Walk each branch toward the common quantity within one shared diagnostic budget.
Memoise an identical compiled read only within its established context/snapshot
scope and carry the original receipt on reuse. Historical ticket follow-ups use
qualified retained evidence; a new current-value question requires a fresh read.
Guard/permission overhead remains separate. No doubled cap, deadline extension
or automatic refill. State the bounded request estimate before any eventual run.

Render the two displayed values, both readable path roles, first common quantity
and the first established split as deterministic facts. The model writes only
a mechanism supported by retained definitions. Differences due to declared
measure/filter/grain rules are separate from judgments of business correctness.
Keep SNAPSHOT_UNVERIFIED unless each value query binds an aligned version report;
never infer currency from equality or exclude timing without evidence. Both
outputs name the question answered, unchecked boundaries, limitations and action.

Reuse existing recorded technical/business handoffs; never send a message or
close for the user. Owner ambiguity is a named gap. Privacy-projected estates
require end-to-end capture support before accepting this new input flow; no raw
fallback. No identity, permission, secret or fixture change is part of this design.

Acceptance after approval: synthetic paired-report tests with independently
calculated quantities; target ambiguity; two figures for one cell; missing common
binding; unsupported scope; different measures; guard/read reuse; partial-budget
stop; snapshot caveats; exact/projected tape contracts; same-ticket follow-ups.
Add fixture-authored live evidence only after the offline gate passes. Do not
change existing goldens or archived expectations to fit the new route. The
current OTHER_REPORT refusal remains until the human approves this design.
