# Mapped value proof, separate from full verification

`VALUE_VERIFIED` means values agree under an explicitly recorded mapping, or an attested numeric recomputation explains the difference. It never means semantic equivalence or business correctness. Existing `VERIFIED` and its resolver are unchanged. Model proposals cannot assign either grade; static `base_confidence` excludes both proof grades.

The new trusted `ValueVerificationResolver` reads retained checks, compiler mappings and successful query receipts from installed stores. Its current-pins reader must supply the selected graph, definition, context scope, mapping and endpoint hashes. Mismatched current pins refuse. The mapping carries the exact report/page/visual address and cell, complete declaration inventory, ACTIVE restrictions, report binding/catalog, parameter/predicate translations and explicit absolute decimal tolerance with its source. The existing report inventory consumer checks conservation and ACTIVE coverage. Unknown declaration forms, missing translations and failed reads do not earn a proof.

Every read carries its actual statement and SHA-256, typed numeric value or explicit BLANK, mapping/scope/definition/endpoint pins, observation timestamp, query-bound declared/reported surface evidence and reportable fields. The existing surface attestation consumer recomputes the grade; partial attestation remains visibly partial. BLANK equals BLANK and differs from zero, failure and absence. A tolerance is never inferred. An unequal pair needs another successful read executing the recorded transformation on one endpoint and reproducing the opposite endpoint's observed value. Comparing a recomputation with itself is refused; a prose explanation is insufficient. The practical mapping itself remains an explicit assumption, not a semantic compiler proof.

`value_path` conserves the required connected dependency edges. Missing edges produce PARTIAL with the reached nodes and exact missing edge IDs, never a complete VALUE_VERIFIED path. All proofs must share estate, graph and declared context scope. Snapshot alignment requires query-bound alignment IDs on every read; otherwise SNAPSHOT_UNVERIFIED remains. Saved slicer-default and partial-attestation qualifications are included in the proof. API coverage renders the distinct grade and qualification separately.

`GraphRepository.value_verify_edges` appends earned history; it cannot downgrade an existing full VERIFIED proof. Definition/endpoint-node changes and unavailable collection stale value proofs just like full proofs. `invalidate_value_proofs` appends a stale version when selected graph, scope, mapping or endpoint pins change, preserving historical bodies and their prior grade.

Schema migration 3 extends only the two current node/edge confidence CHECKs. Migration 1/2 source strings and checksums remain unchanged. PostgreSQL alters the named CHECKs transactionally. Offline SQLite rebuilds the two current tables transactionally, preserving bodies, foreign keys and row values. Graph history is untouched. No deployed migration or estate read is performed by the offline tests.

Producer interfaces and exact closed shapes are in `scripts/investigator/graph_value_verification.py`; the fixture in `scripts/test_graph_value_verification.py` supplies a synthetic example. Native execution failure must be retained as failure, not coerced into a successful proof-shaped read.
