# Round Sixteen C - typed record and aggregate observations

The confirmed-claim dispatcher can use `MicrosoftProcessAdapter.claim_probe(path, layer, request, scope)` through the existing bounded SQL/DAX compiler, diagnostic budget and sealed `flexible_diagnostics` receipt. The adapter accepts explicit semantic-column identifiers and translates them through the retained physical `sourceColumn` and exact Copy mappings. Labels never choose a field. These are observations on the declared semantic-to-landing-to-application Copy chain; the original fixture's transformation path has no earned key/field projection contract and remains a named refusal.

Four requests are implemented:

- Set reconciliation checks presence and count for one to six exact, explicitly supplied integral keys. It cannot discover unknown extra keys or claim a complete set census.
- Multiplicity obtains whole-entity row count, distinct nonnull declared-key count, and null-key rows in one query per layer. Optional named-key details share that query. The SQL and DAX forms exclude NULL/BLANK from the distinct-key count explicitly. Equal counts do not prove the same records, and duplicates are not automatically erroneous.
- Record-value tracing obtains a count and typed field result for each named key. Zero count means no record; one row with BLANK is an observed blank field; more than one row prevents choosing a unique field. An internal aggregate over duplicate keys is never substituted as a record value. Native key predicates use strict equality so key zero cannot include BLANK rows.
- Decomposition sums a retained direct additive integral measure by an explicitly selected integral dimension. It can cover the unfiltered declared entity or a bounded example-key subset. Date/string dimensions, nonadditive measures and untranslatable filtered/time scopes remain unsupported. Grouped sums are not a member-record equivalence proof.

Both surfaces must provide same-statement identity, engine and object self-reports. The expected surface, mapping hash, layer and request are sealed in the read address. The neutral consumer reloads the original receipt, verifies its seal/current model context/request/result, and recomputes typed facts and attestation. Separately, the controller calls the pure `claim_probe_contract` compiler and supplies its expected request hash/address to the reducer. A valid sealed receipt for a different query cannot satisfy that contract. It does not trust a producer's success boolean. Connection fields that are not self-reported remain explicit limits. Every comparison retains `SNAPSHOT_UNVERIFIED`: timing was not excluded. No new route awards DEFECT or a causal outcome.

The consumer orders boundaries from source to presentation. A first-change statement requires every preceding layer to have been observed and attested. Missing layers remain missing, never absent records. Duplicate-key field comparisons are `NOT_COMPARABLE`, even if both sides returned the same arbitrary aggregate. Available evidence remains visible alongside gaps.

Each explicit key has its own transition history. Presence, count and field-value changes are tracked separately: one key disappearing at the landing layer does not hide another key disappearing at the semantic layer, and a prior multiplication does not hide that key's first disappearance. Field-value first-change claims additionally require a unique record at every preceding layer. A duplicate for one key does not erase another key's valid trace. Missing preceding reads prevent a first-layer claim even when a later adjacent change is observed.

Native empty decomposition retains an explicit sentinel row carrying the surface's own report; the typed consumer removes that sentinel. A saturated inner TOPN(200) plus the sentinel yields 201 rows and therefore a PARTIAL outer receipt, never a false complete census. The conservative native success limit is 199 groups. The existing SQL bounded reader also refuses saturated responses. Output limits do not bound the number of rows scanned by an aggregate.

Validation: 23 focused tests pass through the actual adapter, SQL/DAX compilers, fake boundary transports, metering callback and sealed SQLite receipt. They cover cross-surface mapping, source-to-presentation ordering, independent per-key first changes, missing preceding layers, BLANK/absence/duplicate separation, global counts and nulls, strict zero-key equality, native empty and saturated decomposition, unsupported types/scopes/transforms, mismatched attestation, partial/failed reads, stale context, receipt tampering and closed-registry recomputation and a hostile producer that seals a different-key query under the correct address. The combined projection, claim-controller, adapter-factory and existing record-presence/source-delivery/system-of-record run passed 99 tests. No live estate or model calls were used for this implementation.

## DECIDED WITHOUT REVIEW

- Reuse the existing declared Copy mapping and bounded reader path instead of promoting legacy `record_readback` observations, whose own consumer explicitly refuses delivery equivalence.
- Retain the actual original fixture transformation refusal: scalar binding verification is not a key or field projection proof.
- Obtain global multiplicity aggregates alongside any example counts in one diagnostic slot, rather than describing examples as a global census.
- Use an explicit native sentinel only for attestation on empty grouped results; require the receipt's completeness check to reject saturated output.
- Restrict initial decomposition to exact integral dimensions and the retained additive SUM. Broader temporal/string semantics require a separate supported mapping rather than a guessed translation.
